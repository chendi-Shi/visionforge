# 视频库与复核验收 · 2026-10-15

这次改动验证的是多视频工作流与证据纠错，不宣称提升了 VLM 准确率。

## 真实本地检索

- 同一公开街景样片分别截取原片 0–17 秒、24–35 秒，作为两个独立导入的视频。两者不是独立测试集。
- 本地 `qwen3-vl:2b`，原始画面经 FastEmbed CLIP 检索，随后实际调用 Ollama 逐帧核验。
- 整批预算 12 帧、单视频上限 3 帧，实际分配并完成 6 帧。2 个视频均完成，0 次结构失败。
- 视频 A 的 5、6、7 秒均判未见；视频 B 的 7 秒判可见，8、9 秒判未见。B 的 8 秒对应原片 32 秒，仍是漏检：货车在遮挡后仍部分可见。因此模型推导的 B 片 7–8 秒消失区间不可靠。
- 六次核验累计约 524 秒。本次同机运行测试和界面，不是受控性能基准，也不包含全部预处理与索引耗时。

## 用真实漏检验证复核闭环

采用此前保存的原片 32 秒核验记录，而不是伪造模型响应：

1. 开发助手查看原帧，将 `not_visible` 复核为 `visible`。
2. 复核时间线的消失区间由 31–32 秒变为 32–33 秒。
3. 保存 `reset` 后，时间线恢复原模型结论。
4. 再保存修正，三条修订均保留；用户审核数量为 0。
5. 前后 `results`、`attempts`、原始 `intervals` 的组合 SHA256 相同：`4470fe61ee772f1aa3b5c5714039e4b5323ee62737e4950d9e6fc2fbabd30f30`。

## 服务更新后的会话恢复修复

实际页面曾在服务重启后每4秒重复报告 `Value ... is not in the list of choices: []`。原因是浏览器仍保存旧选择，而 Gradio 新会话没有此前动态更新的选项；输入预处理在业务回调之前就拒绝该值。现在3个后台轮询读取服务器会话状态，加载、刷新和页面导航同步更新选项与状态。后台进度刷新不再回写勾选，防止较早启动的轮询覆盖较新的用户选择。已失效的记录会同时清空界面和状态；显式提交、暂停、保存和导出仍使用点击时的当前选择，并保留严格校验。

新增7项使用真实 Gradio `SessionState` 的回归，覆盖会话丢失、选项恢复、会话隔离、失效记录、迟到轮询和立即提交。包含这些检查的289项全量测试及 `pip check` 已通过。实际浏览器中，勾选跨多轮轮询和页面切换仍保留；旧任务打开对应视频并暂停在7秒；连续机器人录像可跳到49.520秒作者起点。新服务日志为空。见[验收记录](../artifacts/workbench-session-recovery.json)与[实际页面截图](../artifacts/workbench-session-recovery.jpg)。这不保证跨版本旧页面热兼容，更新界面版本后仍需刷新页面。

两模型全部64次实验导出后再次更新页面，实际确认两组32/32结果可切换、Qwen作者49.520秒与模型19.480秒各自跳转，以及切到另一段录像后在对应素材的48.720秒播放；没有应用错误弹窗。播放器自动播放后的实际读数、素材对应关系与最终暂停状态保存在[最终验收](../artifacts/temporal-final-workbench.json)，[截图](../artifacts/temporal-final-workbench.jpg)保留了模型定位错误的默认案例。

## 既有视频库范围

仍然采用稀疏画面候选与单帧核验，不做跨镜头身份跟踪、连续动作识别或声音理解。CPU 推理较慢，CLIP 也会漏掉目标；没有检索命中不等于全片不存在。复杂语义推断和穷尽性事件检测尚未实现。
