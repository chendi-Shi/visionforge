# 问题驱动的视频取证

用户目标 → 本地翻译/可编辑英文检索词 → 缓存的 CLIP 画面向量 → 时间去重候选 → 局部加密抽帧 → 独立单帧核验 → 相邻采样可见性区间。

## 复用与职责

`video_media.py` 仍负责 FFmpeg 预览及实际解码时间。`video_index.py` 复用 FastEmbed 的 CLIP 图文双编码器与 ONNX Runtime CPU 后端，直接嵌入画面，不读取旧模型摘要。最多900帧，归一化512维向量约1.8MB，无需额外向量数据库进程。图文模型 revision、权重与预处理文件hash、依赖版本、视频hash、每帧hash和NPZhash随索引保存。

`search_jobs.py` 使用独立SQLite与跨进程worker锁。旧视频worker和新检索worker在实际Ollama调用及完整CLIP阶段共享同一数据目录的 `inference.lock`；进入CLIP前卸载本搜索的VLM，离开时释放CLIP sessions，再逐帧核验。不会停止其他项目进程，项目外负载仍会影响速度。单帧成功后立即保存；暂停在当前调用或索引批次之后生效。服务退出时保留记录，重新启动把正在执行的任务标成paused，等待明确继续。设置、代码或模型digest不同会拒绝复用成功结果。

本地查询翻译保留原始问题、具体核验目标、英文检索词和原始模型输出；用户填了英文词时保留为用户输入。检索词和核验目标都可以查看。CLIP相似度只用于候选排序，不进入可见/未见判定。

## 时间与否定证据

核验模型只输出 `visible / not_visible / uncertain` 与原因，schema没有时间字段。时间由实际解码帧号除以12获得，证据文件校验后才能调用模型。各帧独立请求，不带前一帧描述或对象身份假设。

系统仅在相邻核验采样、间隔不超过设定步长时生成“最后未见—首次可见”或“最后可见—首次未见”区间。`uncertain`、失败、缺失/重复时间和过大间隔都阻断推导。即使两端均可见，也只形成可见证据点组，不能证明中间连续出现，更不构成目标跟踪。遮挡、切镜头和多次进出仍需回看视频。

## 有界资源与可检查失败

默认索引2秒间隔、最多900帧，选2个候选、每个前后2秒、1秒步长、最多12张核验图。超索引预算调整整个时间轴间隔，不截断尾部。核验预算按候选轮转分配；实际采样点全部可见。覆盖之外未知，不以空检索或若干负样本断言全片不存在。

下载失败、向量非法、模型文件改变、视频/帧/NPZ哈希不一致、输出截断、schema无效均显式记录。没有以随机向量、字符串筛选或空结果模拟“索引成功”的回退。原模型输出保留，人或其他程序复核时可以重新检查。

## 验证分层

离线测试检查状态、缓存、排序、预算、哈希、时间区间与导出。真实图像检索检查固定目标的候选命中；真实Ollama对照使用相同帧、问题、分辨率和输出预算。四例标签来自助手目视，未由用户复核，不代表未知视频上的准确率。首次模型加载、缓存和同时运行的程序会影响本机耗时；计时是本次观测，不是通用性能承诺。
