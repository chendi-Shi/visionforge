# 视频检索升级验证 · 2026-10-13

本轮验证使用本机 i5-1130G7、16 GB RAM、CPU，以及同一段 35 秒公开街景视频。机器同时运行其他项目，耗时不是隔离性能测试。所有参考标签及候选画面的目视核查均由开发助手完成，未经用户审核，不代表未知视频上的总体准确率。

## 单帧模型对照

四个固定诊断点包括红头盔人物和 Red Bull 货车的正、负样本；两个模型使用相同 PNG、最长边 448、输出预算 128、同一核验提示和 JSON schema。时间由证据帧提供，不让模型生成。

| 模型 | 结构合格 | 与参考标签匹配 | 不确定 | 负样本误报可见 | 四次调用累计 |
|---|---:|---:|---:|---:|---:|
| Qwen3-VL 2B | 4/4 | 4/4 | 0 | 0 | 355.302 秒 |
| MiniCPM-V 4.6 1B | 4/4 | 1/4 | 3 | 0 | 151.986 秒 |

MiniCPM 的三次不匹配为“不确定”，不能直接称作三次错误识别；也不能把 schema 通过率当准确率。它没有在本小样本中展示更好的实用结果，因此安装脚本和界面默认保留 Qwen。MiniCPM 已成功在本机运行，可在模型列表中选择。

[固定样本与参考标签](../examples/video/grounding-cases.json)；[完整可审计输出](../artifacts/grounding-ab.json)。Qwen 结果来自先前已完成的同配置调用，第二轮复用缓存；MiniCPM 在第二轮执行。公开记录保留模型 digest、代码 SHA、提示、原文、结构化结果及每次耗时，仅相对化私人工作区路径，并说明变换前后的记录哈希。

## 原始画面检索

复用固定 CLIP ViT-B/32 ONNX 图文模型，35 秒视频采样 19 帧，包含首尾；每帧向量来自图片，不来自生成的摘要。首次完成索引 124.658 秒，其中视觉编码 19.741 秒；随后缓存核查 16.945 秒。

- 红头盔查询前两名为 24、28 秒，目视均支持；第三名 34 秒不支持。
- Red Bull 货车首名为 32 秒，目视支持；6、18 秒候选不支持。
- “无人无车的乡间道路”仍返回城市车流候选，不能用排名判断目标存在。

完整五条查询、原始余弦分数、候选 PNG、SHA、模型身份和逐帧助手备注见 [公开检索记录](../artifacts/visual-retrieval/validation.json)；实现与具体性能条件见 [SEARCH_REUSE](SEARCH_REUSE.md)。这些结果验证候选召回，同时暴露误召回与否定条件失效。VLM 独立核验是必要的下一步，不能把 CLIP score 包装成置信度。

## 自动化与实际发现

78 项离线测试通过，覆盖视频时间轴、资源预算、缓存与证据哈希、任务互斥、暂停恢复、只重试失败帧、模型变更隔离、区间阻断、输出结构、导出安全性和公开样片校验。`pip check` 无依赖冲突。依赖锁来自此次实际安装环境。

真实流程发现并修复了中文检索词输出预算不足和模型原样复述中文问题：由 100 提高到 256 tokens，使用中文改写指令，并在 schema 中约束英文检索字段；要求简短英文描述和中文可见目标。截断或无效的翻译原文保留在失败记录中，不继续执行检索。修复后的真实调用将中文问题改写为英文对象描述，保留品牌而不虚构车身颜色。另修复了打开页面时已有检索历史未自动选中的问题。

并行试运行曾造成整机内存压力。正式工作流让完整 CLIP 阶段与旧、新 VLM 调用共享跨进程推理锁：CLIP 前释放本搜索的 Ollama 模型，CLIP 后释放编码器，再开始逐帧核验。不会管理其他项目进程，因此外部负载仍可能使本机变慢。

## 解释范围

只判断实际采样帧中的可见性。相邻未见/可见采样点约束变化区间，不能证明精确起止、持续动作或完整轨迹。未选候选之外保持未知。当前没有音频识别，也未在多种独立视频上完成评估。
